# `floci-gcp` vs `floci-ui`: Supported GCP Services & Resources

Comparison of Google Cloud Platform (GCP) features and resources supported by [`floci-io/floci-gcp`](https://github.com/floci-io/floci-gcp) (the local GCP emulator on port `4588`) and [`floci-io/floci-ui`](https://github.com/floci-io/floci-ui) (the multi-cloud web console on ports `4500`/`4501`).

> **Legend (`floci-ui` status):**
>
> - `✅` Full Explorer CRUD (list, inspect, create, delete)
> - `👁` Read-only or partial UI support
> - `–` Not supported in `floci-ui` (no adapter in `packages/api/src/adapter-gcp/`)

## Comparison Table

## Known limits (verified against `floci-gcp` 0.12.0)

- **Secret Manager works, but Cloud Run jobs cannot read it.** Creating secrets and versions and reading `versions/latest` succeed. Updating a Cloud Run job with an env `valueSource` (`secret_key_ref`) fails with `400: Cloud Run execution does not support env valueSource`. This is a documented limit of Floci's execution mode, not a bug in our Terraform: its [Cloud Run docs](https://github.com/floci-io/floci-gcp/blob/main/docs/services/cloud-run.md) list "secrets" under Not Implemented and say job templates allow "no env `valueSource`". On Floci the Gemini key is therefore a plain env value on the jobs (and in the local Terraform state: use a throwaway key); on real GCP it comes from Secret Manager. See [infra/README.md](../infra/README.md).
